# 비담농장 앱 서버 설치 (구글 시트 + Apps Script)

PC에서 대표 구글 계정으로 진행합니다. 한 번에 약 10분 걸립니다.

**서버는 두 개를 만듭니다**
| 서버 | 시트 이름 | 연결할 앱 주소 |
|---|---|---|
| 시험용 | 비담농장 서버 (테스트) | https://yeemee4.github.io/farm-app-j039ry/test/ (주황 ‘테스트’ 띠) |
| 본서버 | 비담농장 서버 | https://yeemee4.github.io/farm-app-j039ry/ |

**순서:** 아래 1~5단계를 먼저 **시험용**으로 해 보고 확인합니다. 문제없으면 같은 단계를 **본서버**로 한 번 더 합니다.

## 1. 구글 시트 만들기
1. https://sheets.new 를 엽니다. 빈 시트가 새로 생깁니다.
2. 왼쪽 위 제목을 **비담농장 서버 (테스트)**로 바꿉니다. 본서버를 만들 때는 **비담농장 서버**로 합니다.
   - 탭(data, accounts 등)은 서버가 알아서 만드니 손대지 않아도 됩니다.

## 2. 서버 코드 붙여 넣기
1. 시트 메뉴에서 **확장 프로그램 › Apps Script**를 엽니다.
2. 편집기에 `Code.gs`가 열려 있습니다. 안의 내용을 모두 지웁니다.
3. 이 저장소의 `server/Code.gs` 내용을 전부 복사해서 붙여 넣습니다.
   - 주소: https://github.com/yeemee4/farm-app-j039ry/blob/main/server/Code.gs
   - 오른쪽 위 복사 버튼을 쓰면 됩니다.
4. 💾 저장을 누릅니다. 프로젝트 이름은 **비담농장 서버**로 합니다.

## 3. 웹 앱으로 배포
1. 오른쪽 위 **배포 › 새 배포**를 누릅니다.
2. 톱니바퀴에서 **웹 앱**을 고릅니다.
3. 다음과 같이 설정합니다.
   - 설명: `v1`
   - 실행: **나(대표 계정)**
   - 액세스 권한: **모든 사용자**
     - 앱이 로그인 없이 서버에 닿게 하려는 것입니다.
     - 기록을 읽고 쓰려면 앱의 PIN 로그인이 필요합니다.
4. **배포**를 누르면 권한 확인 창이 뜹니다.
   - 대표 계정을 고릅니다.
   - "확인되지 않은 앱" 경고가 나오면 **고급 › 비담농장 서버(안전하지 않음)로 이동**을 누릅니다. 내가 만든 스크립트라서 나오는 경고입니다.
   - **허용**을 누릅니다.
5. 나온 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
   - 이 주소는 저장소나 단체 대화방에 올리지 마세요.

## 4. 앱 연결 (대표 휴대폰부터)
0. **먼저 모든 계정의 PIN을 바꿉니다** (설정 › 계정 관리).
   - 처음 PIN(예시값)은 공개 저장소에 적혀 있어서, 바꾸지 않으면 앱이 서버 시작을 막습니다.
1. 앱에서 대표로 로그인합니다.
2. **설정 › ☁ 서버 연결**에 URL을 붙여 넣고 **연결 확인**을 누릅니다.
3. "서버가 비어 있음(처음 설치)"이 나오면 **이 휴대폰 기록으로 서버 시작**을 누릅니다.
   - 이 휴대폰의 계정, 기록, 설정이 서버로 올라갑니다.
   - 시작하기 전에 **설정 › 데이터 초기화 › 우리 농장 초기값**으로 예시 데이터를 지워 두면 좋습니다.
4. 이름 옆 동그라미가 **초록**이면 연결된 것입니다.
   - 위쪽에 "☁ 동기화됨"이 표시됩니다.

## 5. 다른 휴대폰 연결 (팀장·작업자)
1. 그 휴대폰에서 앱을 열고, 로그인 화면 아래의 **☁ 서버 연결**을 누릅니다.
2. 대표에게 받은 URL을 넣고 **연결 확인 › 서버에서 받기**를 누릅니다.
3. 로그인 화면에서 **그 사람 계정**을 고르고 PIN을 넣습니다.
   - 서버의 기록이 그 휴대폰으로 내려옵니다.
   - 처음 한 번은 인터넷이 필요합니다.
   - 그다음부터는 인터넷이 없어도 그 휴대폰에서 로그인할 수 있습니다.

## 6. 디스코드 알림 (선택)
1. 디스코드 채널 설정에서 **연동 › 웹후크 › 새 웹후크**를 만들고 **웹후크 URL 복사**를 누릅니다.
2. 앱의 **설정 › ☁ 서버 연결 › 디스코드 알림**에 붙여 넣고 **저장·시험 메시지**를 누릅니다.
3. 어떤 기록을 알림으로 보낼지는 같은 화면의 **알림 보낼 기록**에서 켜고 끕니다.

## 서버 코드를 고쳤을 때 (업데이트)
1. **테스트 시트**의 Apps Script 편집기에 새 `Code.gs`를 붙여 넣고 저장합니다. 시험용 앱으로 확인한 뒤, 같은 방법으로 **본 시트**에도 붙여 넣습니다.
2. **배포 › 배포 관리 › ✏️ 수정 › 버전: 새 버전 › 배포**를 누릅니다.
   - 이렇게 하면 URL이 그대로 유지됩니다.
   - "새 배포"를 누르면 URL이 바뀌니 주의하세요.

## 알아 두기
- **보안**
  - 시트에는 PIN 대신 해시(되돌릴 수 없는 값)만 저장됩니다.
  - 디스코드 주소는 스크립트 속성에만 저장됩니다.
- **백업:** 구글 시트의 **파일 › 버전 기록**으로 이전 상태를 볼 수 있습니다.
- **오프라인:** 인터넷이 끊겨도 입력할 수 있습니다. 동그라미가 주황색이고 "보낼 기록 n건"이 보이면, 연결된 뒤 자동으로 보냅니다.
- **같은 기록을 두 사람이 고치면:** 나중에 서버에 닿은 쪽이 남습니다.

## 레규메이트 급여 알림 켜기 (서버 코드 v2부터, 한 번만)
1. Apps Script 편집기에 새 `Code.gs`를 붙여 넣고 저장 → **배포 › 배포 관리 › ✏️ › 버전: 새 버전 › 배포**(주소 그대로).
2. 편집기 위쪽 함수 목록에서 **setupReguTrigger**를 고르고 **▶ 실행** → 권한 창이 뜨면 허용.
3. 왼쪽 ⏰ **트리거** 메뉴에 `reguTick · 30분마다`가 보이면 끝. 디스코드 알림 주소가 서버 연결 화면에 저장돼 있어야 메시지가 갑니다.

## 드라이브 자동 백업 (서버 코드 v4부터, 한 번만)
1. 새 `Code.gs`를 붙여 넣고 저장한 뒤 **배포 › 배포 관리 › ✏️ › 새 버전 › 배포**를 누릅니다.
2. 함수 목록에서 **setupReguTrigger**를 고르고 **▶ 실행**을 누릅니다.
   - 처음에는 **드라이브 권한**을 묻습니다. **허용**을 누르면 됩니다.
   - 백업 파일을 만들 때만 씁니다.
3. 확인
   - **⏰ 트리거**에 `backupTick · 매일`이 보이는지 봅니다.
   - 바로 시험하려면 함수 목록에서 **backupTick ▶ 실행**을 누릅니다. 구글 드라이브에 **비담농장 백업** 폴더와 파일이 생기면 됩니다.
- 매일 새벽 3시에 시트 전체가 파일 하나로 저장됩니다.
- 최근 30일 것은 모두 남기고, 그 전은 매월 1일 것만 남깁니다.

### 비상 복원 (시트가 망가졌을 때만)
1. Apps Script 함수 목록에서 **restoreBackup ▶ 실행**을 누릅니다. 가장 최근 백업 파일로 data·accounts 시트를 되돌립니다.
2. 모든 휴대폰에서 **설정 › ☁ 서버 연결 › 전부 다시 받기**를 누릅니다.

## 휴대폰 보관 기간
- 휴대폰에는 **최근 12개월**의 매일 기록(사료·폐사·이동·약품·재고 등)만 둡니다.
- 모돈 번식 기록(교배·임신확인·분만·이유·양자·도태·도입·BCS·동기화)은 기간과 상관없이 모두 둡니다.
- 그 전 기록은 서버와 드라이브 백업에 그대로 있습니다. **성적·타임라인 › 📂 예전 기록 보기**에서 기간을 골라 볼 수 있습니다(보기 전용).

## 서버 새로 시작 · 되돌리기 (서버 코드 v5부터)
- 앱 **설정 › 데이터 초기화**에서 대표만 쓸 수 있습니다. 서버에 연결된 경우입니다.
- **서버 새로 시작**: 농장 이름을 직접 입력해야 실행됩니다.
  1. 드라이브에 '새로 시작 전' 백업을 만듭니다.
  2. 이 농장의 기록·모돈을 **'보관 농장 날짜' 시트로 옮깁니다**(지우지 않음).
  3. 설정·계정·PIN은 그대로 둡니다. 다른 휴대폰들은 다음 동기화 때 자동으로 새 상태를 받습니다.
- **되돌리기**: 보관 시트를 고르면 그 기록이 제자리로 돌아옵니다. 그 사이 기록은 다시 보관 시트로 갑니다. 아무것도 지워지지 않습니다.
- 휴대폰의 '다시 받기'는 그 휴대폰만 서버 기록으로 다시 받습니다. 아직 못 보낸 기록이 있으면 멈춥니다.
